# データ取得可能性調査報告書

調査日：2026年11月8日（日本時間）／対象：京成バス千葉セントラル・長沼営業所、稲31・稲32、稲31深夜

## 結論

**対象路線のデータを合法的かつ継続的に取得し、独自画面へ再表示できる提供元を、今回の調査では確保できませんでした。リアルタイムアプリを実装可能とは判定しません。**

公式バスナビには対象停留所の時刻表・接近情報が掲載されています。しかし、その利用条件はデータの自動収集、解析、複製・公衆送信等を禁止しています。公開画面の存在を独自API利用の許可と解釈できません。[公式の利用条件](https://transfer-cloud.navitime.biz/keiseibus-group/terms-of-use)

ODPT・GTFSデータリポジトリで見つかった京成の候補は、京成バス千葉ウエスト・塩浜営業所（旧京成トランジットバス）のものです。実際にZIPを取得して検査したところ、稲毛駅・長沼原町の停留所名も、稲31・稲32も一致しませんでした。このフィードは採用しません。[ODPTの対象範囲](https://ckan.odpt.org/dataset/keisei_transit_bus_all_lines)、[取得したカタログAPI](https://api.gtfs-data.jp/v2/feeds?pref=12)

NAVITIMEには正式な時刻表・停車駅一覧APIがあります。ただし別途契約と認証が必要で、今回の対象路線・項目が契約上取得できるか、リアルタイム情報も提供されるかは未確認です。公開仕様書のサンプルを対象便の実測結果として扱っていません。[時刻表API仕様](https://api-sdk.navitime.co.jp/api/specs/api_guide/transport_diagram-segment.html)、[停車駅一覧API仕様](https://api-sdk.navitime.co.jp/api/specs/api_guide/transport_stops.html)

## 調査方法と判定の範囲

公式サイト・正式API仕様・公開カタログを調べ、許諾された公開カタログAPIへのGETと、CC BY 4.0の候補GTFSの取得・解析を実施しました。公式バスナビは検索・閲覧ツールの取得済みページで掲載内容を確認しましたが、サーバーからの直接GETはCloudFrontのHTTP 403でした。規約確認後は自動収集や内部API探索を進めていません。

公式ページの取得済みテキストにはキャッシュが含まれ得ます。検索結果の取得時刻、公式画面内の表示時刻、GPS測位時刻、サーバーの受信時刻を同一視していません。対象路線の最新JSON、GTFS-RT、GPS座標の実受信成功はありません。

「見つからない」は、今回の公式公開資料・ODPT検索・GTFSデータリポジトリの検索範囲で未発見という意味です。非公開契約データの不存在を断定するものではありません。

## 機能別の実現条件と代替表示

| 要件 | 現時点での扱い | データ確保後の表示 |
| --- | --- | --- |
| F-01 方向切替 | 実装可能なUI機能。Phase 1承認後に着手 | ワンタップ切替とlocalStorage保存 |
| F-02〜04 便一覧・到着・乗車時間 | 対象データ待ち。架空時刻を運行情報として公開しない | 同一便の両停留所時刻、各値の情報種別、欠測表示 |
| F-05 現在位置 | 対象GPSも再利用可能な接近区間データも未確保 | GPSあり：実座標と測位時刻。区間情報のみ：区間図と観測時刻、GPS未取得を明記。両方なし：現在位置不明 |
| F-06 自動更新 | 取得元の許可・頻度待ち | 受信・観測時刻を分離。許可頻度内で共有キャッシュ、非表示時抑制 |
| F-07 到着順比較 | 同一便の到着予測を複数取得できる場合に実装 | 乗車順／目的地到着順の切替、後続便先着の注記 |
| F-08 レイアウト | 実装可能なUI機能。Phase 1承認後に着手 | スマートフォン優先、文字拡大・地図ピンチ操作を維持 |
| F-09 エラー | 対象データの仕様に合わせて実装 | 通信失敗、欠測、運休、対象便なし、期限切れを区別 |

GPSがない理由は「対象の正式な配信元・利用許諾を確保できていない」ためです。車両にGPSがない、または運行会社が座標を保有していないという意味ではありません。到着予測も同様です。

## 承認を求める進め方

**推奨案A：正式APIまたは運行会社からの提供許可を確保し、対象実データの追加検証後にMVPを実装する。** NAVITIMEの時刻表だけで満たせると判断せず、リアルタイム・同一便照合・再表示許可を個別に確認します。費用・契約申し込み・外部への問い合わせ送信は今回実施していません。

代替案B：要件を変更し、方向切替・公式ページへのリンクを中心にした簡易版を作る。自動収集・時刻表転載・iframeによる埋め込みは前提にしません。独自の到着予測、乗車時間、遅延、現在位置、到着順比較は提供できないことを明記します。

時刻表だけの版も、対象路線の有効な時刻表と再利用許諾が必要です。許諾がない状態での代替にはなりません。

要件定義の「この段階で、利用するデータソースと実現可能な表示方式についてユーザーの承認を取得すること」に従い、本調査結果と選択肢を確認いただいてからPhase 1へ進みます。今回、実装・公開を完了したとは扱いません。
